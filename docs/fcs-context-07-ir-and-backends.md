## 1. 구조의 정본은 IR 하나다

**[확정]** `claw/fcl/graphs.py`의 그래프 선언이 구조 그 자체이고, `Autopilot`·`Scas`·`Mixer` 등
클래스는 파라미터를 보유하고 그 그래프를 태우며 원시 항법 상태를 공학량으로 바꿔 주는
**어댑터**다. 설계 실행(Python 백엔드)과 탑재 C(C 백엔드)가 같은 선언에서 나오므로 어긋날 수
없고, "Python과 C를 둘 다 운용할지"는 나중에 정해도 되는 **백엔드 선택**으로 남는다.

제어법칙 구조가 명령형 Python 안에 있으면 프로그램이 읽을 수 없어 C를 뽑을 수 없다 — IR은 그
연결을 데이터로 적은 것이고, Simulink `.slx`가 맡는 자리다. 다만 `.slx`가 **파일 포맷**인 것과
달리 이 IR은 **메모리 상의 파이썬 객체**다: 별도의 IR 언어도 직렬화 규격도 없다.

소비자는 둘이며 **같은 IR을 읽는다** — 그래서 어긋날 수 없다:

| 백엔드 | 파일 | 담당 |
|---|---|---|
| Python 실행 | `codegen/ir_exec.py` | 설계·시뮬, 대조 기준 |
| 탑재 C 생성 | `codegen/emit_c.py` | FCC에 실릴 제어법칙 코드 |

- 부수 규칙: 조립된 뒤 **상태는 조립의 러너 한 곳에만** 있다. 자식 인스턴스에 웜스타트를 넣으면
  법칙 실행에 반영되지 않으므로 조립에 넣는다(`Scas.reset(states=…)`). 실제로 이걸 어겨 트림
  웜스타트가 사라진 적이 있고, 지금은 그 경로가 조용히 무시되는 대신 예외로 터진다
- 비용은 쟀다: 데모 미션 180 s 폐루프가 11.08 s → 11.37 s (**+2.6%**). 6DOF·공력이 지배적이라
  IR 순회 오버헤드는 묻힌다
- **[확정] 조립 정본은 M7이다** — 생성기(`flight/generate.py`)도 서버 라우트도
  `assemble_law(profile, standard=True).init(dt).runner`(02 §5.6)를 쓴다
  (표준 템플릿은 07 §6.2). 03-v0.14까지는 generate.py가
  `fcl_graph(...)`를 따로 불러 게인·타면 한계·마진을 재기술하고 있었고(02 §5.5 위반), 통합 후
  산출물이 **바이트 단위로 동일**함이 등가성 증거다

## 2. C 생성 가능 제약을 IR 단계에서 강제한다

**[확정]** 선언 순서 = 실행 순서(전방 참조 금지 → 대수 루프 원천 차단), 정적 크기, 출력에
도달하지 않는 노드 금지(생성 C에 dead code 없음 — DO-178C 논점). **"Python으로는 되는데 C로는
안 되는" 그래프를 애초에 만들 수 없어야** 나중의 C 전환이 재작업이 아니라 백엔드 추가가 된다.

검사는 두 층에 나뉘어 있다 — 노드 생성자가 **자기 자신**을, `Graph.__init__`이 **연결**을 본다:

| 자리 | 보는 것 |
|---|---|
| `Op.__init__` | 연산별 입력 개수(arity) |
| `Node.__init__` | 블록 노드는 입력 0개 금지 |
| `Graph.__init__` | 전방 참조 금지, 출력 도달성, enable·group 영역의 연속성, 예약 인자명, id 충돌 |

식별자 형태와 C 예약어 충돌은 `_check_ident` 한 곳이 보고, 노드·연산·그래프·이름표가 모두 그것을
부른다 — 어느 층의 전용 검사가 아니다.

- **[설계 유의]** "정적 크기"는 **어느 층에서도 검사되지 않는다** — 모든 신호가 스칼라라 크기가
  자명하게 정적일 뿐이다. 신호에 모양(shape)이나 자료형을 실으려면 그 검사가 갈 자리가 지금
  없고, 새 패스를 만들어야 한다 — 자료형의 현재 한계는 §8, 미결 목록은 §10이다
- **[확정]** 미등록 블록은 **생성 시점에 거부된다** — 지금 탑재할 수 있는 어휘가 곧 C
  에미터를 가진 블록 집합이다 (§10)
- **[확정] 죽은 코드와 비활성 코드를 가른다** (v1.12) — 죽은 코드는 어떤 값으로도 실행되지
  않는 코드이고 IR이 도달 불가 노드를 거부해 원천 차단한다. 비활성 코드는 구조가 고정된 탓에
  코드에는 있지만 **파라미터 값으로 꺼진** 경로다: ki = 0 적분기의 가드 증분 조건, 게인 0 항,
  tau = ∞ 워시아웃, 1점 표의 구간 탐색. 예전에는 ki = 0이면 적분기를 접었는데(값이 구조를 바꾼
  자리) 그 폴딩을 없앴다. 비활성 코드는 검증 탭이 목록화하고, 구조적 커버리지는 파라미터 세트
  합산으로 잰다(§9)

## 3. 모드 분기는 enable 영역으로 표현한다

**[확정]** 제어법칙에는 "축이 비활성이면 명령필터가 측정을 추적하고 헤딩 적분기를
소거한다"(`autopilot.py:147`) 같은 상태 부작용이 있어 순수 데이터흐름으로는 표현되지 않는다.
Simulink의 Enabled Subsystem과 같은 의미론을 노드 단위로 두고, 같은 enable을 가진 **연속**
노드가 한 영역이 되어 생성 C의 `if/else` 한 덩이가 된다. 비활성 스텝에는 노드를 실행하지 않고
`on_disable` 상태 대입만 한다.

최상위의 항법 무효 홀드(`law.py:86`)는 **그래프 전체의 enable** — 아무것도 실행하지 않고 직전
출력을 그대로 내며 상태도 동결된다.

## 4. 생성물 구성 — 역할축과 기능축

**[확정]** MATLAB Embedded Coder를 **두 축으로** 따른다.

| 축 | 분할 |
|---|---|
| 역할축 | `.c`(알고리즘) / `_params.c`·`.h`(파라미터 로더 — 이미지 → rtP 구조체, §6.1) / `_types.h`(자료형 — 파라미터=rtP(표는 포인터+점 수)·상태=rtDW·dt 매크로) / `.h`(진입점·빌드 요구) |
| 기능축 | 서브시스템별 `{base}_{group}.c`·`.h`, `{base}.c`에는 조립부만 |

MATLAB의 `File packaging format: Modular` + 서브시스템
`Function packaging: Nonreusable function` · `File name options: Use subsystem name`에 해당한다.
목적은 FCC팀이 **서브시스템 하나만 떼어 읽고 검증**할 수 있게 하는 것이다.

**[확정] 기능축 분할은 IR을 계층화하지 않는다.** 분할 단위는 IR 노드의 이름표(`grouped`)이고
**IR은 평탄한 채로 남는다** — 계층화하면 호출 규약이 IR로 올라와 선언순서·도달성·enable 검사가
전부 계층을 인지해야 하고, "선언 순서 = 실행 순서 = 생성 C 문장 순서"라는 성질을 잃는다. 경계를
넘는 신호를 인자로 만드는 일은 에미터가 IR에서 계산한다(`_interfaces`). Python 실행기는 이름표를
**아예 읽지 않으므로** 분할이 실행 결과를 바꿀 수 없다.

- 경계를 넘는 신호는 함수 인자가 되며 **이름이 그대로 유지된다** — 정의부 지역변수도, 인자도,
  호출부 지역변수도 `ap_theta_out_y`다 (`rtb_Sum_p_idx_1` 류를 만들지 않는다는 요구가 경계에서도
  지켜져야 한다). 블록 id와 신호 이름은 파티션 경계를 넘어서도 보존해 FCC팀이 읽고 시험할 수
  있게 한다
- 파라미터·상태 구조체는 **쪼개지 않는다**. 파티션 함수들이 `{base}_params_t`·`{base}_state_t`
  포인터를 함께 받으므로 `{base}_reset`과 범프리스 웜스타트 계약이 그대로 남는다
- enable 영역이 group 경계를 가로지르면 IR이 **거부한다** — `if` 한 덩이가 두 함수에 걸칠 수
  없다. 이름표는 연속이어야 하고, 붙일 거면 전부 붙여야 한다(일부만 쪼갠 코드는 "나머지는 어디
  있나"를 읽는 사람에게 떠넘긴다)

**[확정] 공용 헬퍼는 산출물마다 복제하지 않고 `claw_rt.c`·`.h` 한 벌로** 낸다(`emit_runtime` —
MATLAB `slprj/ert/_sharedutils/` 대응) — 같은 코드를 산출물 수만큼 검증하지 않기 위해서다. 쓰는
것만 내고(안 쓰는 헬퍼는 탑재 코드의 dead code다), 산출물이 여럿이면 **헬퍼 합집합으로 한 번**
만든다. 산출물별로 따로 내면 헬퍼가 적은 쪽이 덮어써 링크가 조용히 깨진다.

## 5. 이산 계수 — dt는 형상의 일부다

**[확정] 이산 계수는 생성 시점에 계산해** 파라미터 이미지로 낸다(§6.1) — 탑재에서 `exp()`
등 libm 호출을 없애 결정론을 확보한다. 계수는 엔진이 `init(dt)`에서 계산한 값을 인스턴스에서
그대로 읽는다(이산화 공식이 두 번 적히지 않는다).

부작용: **주기(dt)가 형상의 일부**다. 생성 코드에서 dt는 튜닝 가능한 파라미터가 아니라
매크로라 구조 지문에 들어가고, 이미지 헤더에도 dt가 실려 로더가 매크로와 **비트로** 대조한다
— 다른 주기로 계산한 계수를 실은 이미지는 적재 단계에서 거부된다.

## 6. 생성의 결정성과 지문 — 구조와 값

**[확정]** 생성은 **결정적**이다(생성 시각 미포함). 산출물을 커밋하므로 "재생성했더니
달라졌다"가 곧 실제 설계 변경이어야 한다. 순서원은 dict·tuple이거나, 집합을 돌더라도 **값이
겹치지 않는 전순서 키로 정렬한다**. 전순서만으로는 모자란다 — `sorted`는 안정 정렬이라 키가
겹치면 동점 순서를 입력 순서, 즉 집합 순회 순서가 정한다. `_interfaces`의 `ext`가 그 자리인데,
노드 id가 유일하고(`Graph`가 강제) `ext`의 원소가 전부 선언된 노드 id라 선언 인덱스 키가 반드시
존재하고 안 겹친다. 집합을 그냥 순회하면 안 된다. 파이썬은 프로세스마다 문자열 해시 시드를
바꾸므로, 방출 순서가 어디선가 집합 순회에서 나오면 산출물이 기계마다 달라지고, 그러면 지문이
형상의 신원이라는 성질이 「형상이 바뀌었다」는 오진으로 되돌아온다. 커밋본 대조는 한 프로세스·한
시드에서만 도니 그 어긋남을 못 본다 — 시드를 바꿔 별도 프로세스로 방출해 대조하는 검사가 따로
있다 (`test_ir.py`의 결정성 검사). 그 검사는 `emit_c`와 **`emit_runtime`을 함께** 밀어야 한다 —
집합을 받는 공개 함수가 후자뿐이라 거기가 제일 새기 쉽다.

**[확정] 지문은 둘이다** (v1.12 — 종전 단일 「형상 지문」을 대체한다). 종전 지문은
그래프·파라미터 값·dt를 한데 해시해서, 값만 바뀌어도 모든 파일 배너가 움직였고 거꾸로 에미터
문장이 바뀌어도(v1.11 조건부 적분 보강) 움직이지 않았다.

| 지문 | 해시 대상 | 같다는 뜻 |
|---|---|---|
| 구조 지문 | 생성 C 파일 텍스트(지문·엔진 버전 자리는 표식인 채) + 부르는 공용 헬퍼의 시그니처·본문 | 산출물 파일이 바이트 동일하고 부르는 헬퍼가 같다 |
| 파라미터 지문 | 이미지에 실리는 필드 이름 → 값(`repr`) | 장입하는 값이 같다 |

- 구조 지문은 **텍스트 자체의 해시**라 dt 매크로·파일 분할·에미터 문장이 전부 드러난다. 엔진
  버전은 뺀다 — 같은 코드를 내는 버전 올림이 구조 변경으로 보이면 안 된다
- 파일 분할은 구조 지문을 바꾸고 파라미터 지문과 이미지 레이아웃은 바꾸지 않는다
- **공용 런타임 파일 자체는 해시하지 않는다** — `claw_rt.c`·`.h`는 산출물 전체 헬퍼의 합집합으로
  한 벌 만들어지므로(§4) 산출물 하나의 지문에 넣을 수 없다. 헬퍼 시그니처·본문은 들어가고,
  머리말 (`CLAW_PRM_MAGIC`·`CLAW_PI`·`sizeof(double)` 검사·포함)과 주석은 빠진다
- 두 지문 모두 M1 `canonical_hash`를 재사용한다(`emit_c._structure_fingerprint`·
  `_param_fingerprint`). 커밋 산출물의 현재 값은 `flight/gen/` 배너와
  `flight/tests/test_parity.py`가 못박는다. 결과 meta·응답은 둘을 함께 싣고, 옛 결과의 단일
  지문은 화면이 「구 형상 지문」으로 읽는다

### 6.1 파라미터 이미지 형식 v1

**[확정]** 생성 C에는 구조만 있고 값은 **바이너리 파라미터 이미지**에 있다(사용자 결정 —
C 데이터 파일을 재링크하지 않는다). 비행 전에 장입하고 비행 중에는 바꾸지 않는다.
팩커·판독기·의미 검사는 `codegen/param_image.py`, 로더는 산출물마다 생성되는
`{base}_params.c`·`.h`다. 형식 상수(표식·버전·상태 코드·헤더 크기)는 `emit_c`에 한 벌만 있고
둘이 함께 쓴다.

리틀엔디언, IEEE-754 double. 헤더는 8바이트 경계로 맞춘다.

| 오프셋 | 크기 | 필드 |
|---|---|---|
| 0 | 8 | 표식 `"CLAWPRM\0"` |
| 8 | 4+4 | 형식 버전(1) · 헤더 바이트 |
| 16 | 8 | 구조 지문 (u64) |
| 24 | 8 | 파라미터 지문 (u64) |
| 32 | 8 | 계보 — 이 값을 낸 기체 프로파일 지문 (u64, 모르면 0) |
| 40 | 8 | dt (double) |
| 48 | 4×4 | 스칼라 수 · 배열 수 · double 총수 · 예약 0 |
| 64 | 4×배열 수 | 배열 길이 (u32), 8바이트 경계까지 0 |
| 헤더 끝 | 8×총수 | 스칼라 → 배열 (레이아웃 순서) |
| 끝 | 4+4 | CRC-32(앞 전체, zlib 규격) · 0 |

- **표는 포인터와 점 수다** — 자료형 헤더는 `const double *x_bp; const double *x_val; int x_n;`
  (다항 표는 경계·계수·센터·스케일 포인터와 `nseg`·`stride`)를 갖고, 점 수는 로더가 이미지의
  배열 길이에서 채운다. **표 크기에 코드 상한이 없다** — 상한은 이미지 길이와 호출자 pool이다
- **로더 API** — `{base}_params_pool_size(img, len, &n)`가 헤더를 검사하고 double 총수를 낸다.
  호출자가 그만큼의 pool을 마련하고 `{base}_params_load(img, len, pool, n, &out)`가 값을
  복사해 구조체를 조립한다. 동적 할당이 없고, 바이트로 읽어 복사하므로 이미지 버퍼의 정렬·별칭
  문제가 없다. 실패하면 `*out`을 건드리지 않는다
- **로더 검사 순서와 상태 코드** — 길이(E_SHORT) → 표식(E_MAGIC) → 버전(E_FORMAT) → 헤더
  크기·예약 칸 0(E_HEADER) → 구조 지문(E_STRUCTURE) → dt 비트(E_DT) → 스칼라·배열
  수·총수(E_LAYOUT) → 전체 길이(E_LENGTH) → CRC·그 뒤 예약 칸 0(E_CRC) → pool 크기(E_POOL) →
  유한값(E_NONFINITE) → 표 모양(E_TABLE: 길이 일치·절점 순증가·다항 정합). 검사는 전부 단일 조건
  `if`다(MC/DC 판정 형태 제한). 표 모양은 분기 없는 헬퍼의 비트 OR로 모아 한 번에 판정한다 —
  표마다 `if`를 두면 표 수만큼 손상 이미지가 있어야 분기 커버리지가 닫힌다
- **의미 검사는 이미지를 쓰기 전에 한다** — 유한값·표 모양·한계 순서(lo ≤ hi)·이산 계수 범위.
  하나라도 어긋나면 이미지를 만들지 않는다(서버 422). 로더는 모양만 다시 보고 한계 순서·계수
  범위는 보지 않는다(§10)
- **예약 칸은 0이어야 한다** — 오프셋 60과 CRC 뒤 4바이트를 v1 로더가 0으로 요구한다. 받아
  넘기면 v2가 그 자리에 뜻을 붙일 수 없다. 헤더 패딩은 지금 생기지 않는다(표마다 배열이
  2개·4개라 배열 수가 짝수다)
- **엔디언·표현형** — 읽기는 바이트 조립이라 호스트 엔디언과 무관하다. double이 8바이트가
  아니면 `claw_rt.c`가 컴파일되지 않고, IEEE-754가 아니면 dt 비트 대조에서 거부된다
- 장입 매체·보관·BIT·장입 절차는 FCC 몫이다(02 §1)

### 6.2 표준 템플릿 — 값이 구조를 바꾸지 않는다

**[확정]** 같은 템플릿(`law.template` = `delta_elevon_v1`)의 기체는 **탑재 C 한 벌**을 나눈다.
탑재 C 생성과 검증은 표준 그래프(`fcl_graph(standard=True)` — `assemble_law(standard=True)`)를
쓰고, 시뮬·해석·영향성은 분석 그래프를 그대로 쓴다(노드 수·속도·골든 불변). 분석 그래프에서
값이 구조를 바꾸던 자리를 표준 그래프는 전부 값으로 가둔다.

| 값 | 분석 그래프 | 표준 그래프 | 비트 동일 근거 |
|---|---|---|---|
| 스케줄 안 한 게인 자리 | 파라미터 상수 | 설계 상수의 1점 표(`PointTable`), 카탈로그 16자리 전부 룩업 | n < 2면 `val[0]`을 그대로 반환 |
| `k_rate` = 0 | 레이트 경로 없음 | 경로 유지, 게인 0 | 감쇠 ±0.0 — PID 판정·합이 같다 |
| `washout_tau` = 0 | 워시아웃 노드 없음 | 노드 유지 + 이미지 플래그 선택(`switch_param`)이 원 신호를 고른다 | 선택이 u를 그대로 낸다 |
| 선회 FF 계수 = 0 | FF 노드 없음 | 노드 유지 | θ ± 0.0, 재클램프가 항등 |
| `ki` = 0 | (에미터가 적분기를 접었다) | 적분기 유지 | Python 정본은 원래 매 스텝 적분한다 |
| α 보호마진, 배분 예산 B | `add_const` 리터럴 | `add_param`(값은 이미지) | x + (−c) ≡ x − c |

- **구조를 바꾸는 것은 요청의 명시 옵션뿐이다** — 제어주기, 스케줄 끔, 리미터 끔, 절점 표 대
  다항 표(자리마다), 스케줄 축. 바뀌면 구조 지문이 드러낸다. 1.0(하중 = 증분 + 1)·Gain(−1)·
  스로틀 [0, 1]·모드 임계 0.5처럼 식에 속하는 값은 템플릿 상수다
- 기체 값이 없어서 구조가 달라지는 경우(엘레본 배분 표 없음)는 `TemplateError`로 사유와 함께
  거부한다(서버 422 — 「기체 탭에서 δe_trim 도출」)
- 증명은 flight 패리티다 — 한 번 컴파일한 실행 파일로 구 합성 기체·200 kg급 예제·EO/IR형
  이미지를 돌려, 각 기체의 **분석 그래프** 기록과 비트 일치를 본다(§9). 세 기체의 생성 C는
  바이트 동일하고 구조 지문 하나를 나눈다. 파라미터 지문은 구 기체와 예제가 다르고 EO/IR형은
  예제와 같다(질량·관성만 바꾸는 변형이고 δe_trim을 두 형상을 함께 재어 도출했다). 이미지
  바이트는 계보 칸이 달라 셋 다 다르다

## 7. 입력 경계 — 이미 계산된 공학량

**[확정]** 생성 제어법칙의 입력 경계는 **이미 계산된 공학량**(θ·φ·ψ·p·q·r·V·α·β·h·ḣ·mach)이다.
실기 FCC에서 오일러각·에어데이터·마하는 항법·ADC가 주는 값이고, `fcl/boundary.py`가 이를 직접
계산하는 것은 우리 시뮬레이터가 원시 상태(쿼터니언·NED 속도)를 넘기기 때문이다. 그 변환은 생성
코드 밖(통합 계층)에 남는다 — 쿼터니언 연산을 탑재 코드에 넣지 않아도 되고, FCC의 실제
인터페이스와도 맞는다.

- **[설계 유의]** 불리언도 이 경계에서 접힌다 — `nav_valid`와 축별 활성 플래그 5개가
  `float(bool(...))`로 double이 되어 들어간다. 불리언 **표현형**이 없어서다(§8)
- **[기본값] 경계 조립의 정본은 `fcl/boundary.py` 하나다** — 계약(`GuidanceCommand`·
  `NavOutput`) → 그래프 입력 23키가 `graph_inputs(cmd, nav)` 한 함수에서 나오고, 법칙과
  대조 기록이 **같은 함수**를 부른다. 전에는 같은 목록이 세 벌로 손에 적혀 있었다:
  `law.py`의 kwargs · `verify/trace.py`의 dict · 그 파일의 `INPUT_ORDER`(C 하네스의 stdin
  순서). **키 누락은 런타임에 잡히지만 접기 규약의 어긋남은 아무도 안 봤다** — 한쪽만
  `float(x)`가 되면 0/1 아닌 값이 그래프 enable에 실리고 두 벌이 그대로 돈다. `DIRECT`
  표가 계약 필드를 그대로 읽는 11개를 직접 구동하고, 파생 12개(사원수 → 오일러 · 항법 →
  공력각 · `V/a`)는 출처를 **슬롯까지** 기계 판독 가능하게 적어 둔다. 축 단독
  경로(`fcl/scas.py`)도 그 파생 계산(`nav_derived`)을 함께 쓴다 — 거기서 여섯을 손으로
  또 뽑고 있었고, 언패킹 순서가 갈려도 아무도 안 봤다

## 8. 자료형 — 의미는 선언하고, 표현형은 아직 double 하나다

**[한계]** IR 노드에는 자료형 필드가 없고 생성 C는 전 신호가 `double` 스칼라다. 불리언은 0/1
double로 나르고(`gt` 연산의 출력, enable 비교), 단위(rad·m/s)는 **생성 C에** 남지 않는다 —
IR 선언에는 아래대로 적을 수 있다.

- **배정밀도는 잠정 선택이다** — 대조 차이를 "알고리즘 오류"와 "정밀도 손실"로 분리하기 위한
  것이고, float32 강제 여부는 인증 등급(DAL) 결정이 좌우한다 (02 §9). 그 정책을
  `verify/static_c.py`가 토큰 `float` 금지로 집행한다
- **[기본값] semantic 타입 어휘가 들어왔다** — 신호의 의미(각도·각속도·무차원·불리언)와
  단위·기대 범위를 `Graph(signal_types=…)`로 선언한다. 어휘 정본은
  `codegen/irtypes.py`이고 단위 철자는 `conventions.md` §3의 기계 판독본이다. **선언은
  아무것도 만들지 않는다** — 두 백엔드는 이 모듈을 import조차 하지 않으며(테스트가 `ast`로
  단정) 생성 C·두 지문·노드 서명이 전부 불변이다
- **[기본값] fcl의 일곱 그래프가 전부 선언을 들고 있다** — 이름→타입 정본은
  `fcl/graphs.py`의 `SIGNAL_TYPES` 한 표이고 그래프별 표는 그 부분집합이다(같은 `theta`가
  그래프마다 다른 타입을 갖는 것을 표현 불가능하게 만든다). FCL 경계 23개는 빠짐없이
  선언되고 **미선언은 하나도 없다**. 스케줄 게인만 물리량 미지정(top)인데 그것은 누락이
  아니라 결론이다 — 게인은 오차→출력의 비라 자리마다 차원이 다르고 `kp` 하나만 봐도
  셋이다(SCAS 자세축 무차원 · 속도축 s/m · 고도축 rad/m). 하나의 GAIN 타입으로 묶으면
  거짓이 되므로, 「물리량 없는 실수」라고 **명시적으로** 적어 「아무도 안 봤다」와 가른다.
  이유를 적어 둔 미지정과 안 적은 미지정이 **같은 타입**이도록 `desc`는 타입의 신원에서
  뺀다 — 안 그러면 §10이 다음 단계의 전제로 세운 「미지정은 무엇과도 통일된다」가 통일을
  `==`로 구현하는 첫 시도에서 바로 깨진다
- **[기본값] 계약 경계는 출력도 선언한다** — 믹서 산출물 다섯(`SurfaceCommand`)이 그것이고,
  밖으로 나가는 값은 선언으로 못박는다. 선언의 **내용**은 저장소의 독립 근거가 지킨다:
  계약(`common/contracts.py`)의 `# [rad]`·`# [m/s]` 주석, `law.py`의 경계 조립
  (`p, q, r = nav.omega_b`), 실물 `Saturation`의 범위, `ParamDef.unit`
- **[기본값] 내부 노드는 기본이 미선언이되, 논거가 붙으면 적는다** — 실물 fcl에서 그런 것이
  둘이다: α 리미터 사슬과 게인 스케줄이 낳는 게인(목록의 정본은 `fcl/graphs.py`의
  `_limiter_types`·`_sched_gain_types`). 리미터 사슬을 적는 이유는 `lim_cap = Sum(theta,
  a_margin)`이 §10 「각도의 세분화」의 정당한 반례를 주석이 아니라 **거부되는 한 줄**로
  남기기 때문이고, 게인을 적는 이유는 「낳는 자리에선 무명, 받는 자리에선 유명」을 닫기
  위해서다. **리미터 선언은 순수한 재량이 아니다** — `fcl_graph`의 경계 출력
  `limiter_active`·`alpha_margin`은 `_typed_outputs`를 지나지 않고 이 선언에만 기대므로,
  「내부 선언은 대조 대상이니 걷자」가 되면 탑재 그래프의 경계 출력 둘이 조용히 미선언이
  된다. 같은 신호가
  그래프에 따라 경계이기도 내부이기도 하다 — 스케줄 게인은 `gain_schedule_graph`에서는 경계
  출력이지만 최상위 `fcl_graph`에서는 내부 노드다. **「내부는 비어 있다」는 다음 단계가 기댈
  수 있는 전제가 아니다**: 규칙 추론이 들어오면 이 선언들은 추론의 입력이 아니라 **대조
  대상**이어야 두 벌이 되지 않는다
- **[확정] `expected_range`는 힘이 없다** — 분석·계약 검사용 메타데이터일 뿐이고, 실제 포화는
  설계 요소인 `Saturation` 블록으로만 표현한다. 여기에 힘을 주면(clamp를 낳으면) 그 값이 설계
  의도가 아니라 런타임 동작이 되고, 나중에 고정소수점이 이 값을 스케일 근거로 쓸 수 없게 된다
- **[기본값] 타입 규칙이 들어왔다** — 블록 10종·연산 7종의 입력→출력 규칙과 그래프 전방
  1회 주행이 `codegen/typerules.py`에 있다. **선언은 추론의 입력이 아니라 대조 대상이다**:
  추론은 그래프 입력의 선언에서만 출발하고, 내부 노드의 선언을 만나면 덮어쓰지도 무시하지도
  않고 어긋나는지 본다. 이 방향이라야 규칙과 선언이 두 벌이 안 된다 — 베낀 사본이면 갈라져도
  조용하지만, 추론이 맞는지 묻는 물음이면 갈라질 때 시끄럽다
- **[확정] 확신하는 것만 거부한다** — 미지정(top)은 무엇과도 통일되고, **명시적으로 적은
  미지정**(`it.REAL`·`SCHEDULED_GAIN`)도 그렇다. Gain·Lookup·PID·Product의 출력은 top이다:
  변환이 파라미터 단위에 사는데 그것을 읽으면 검사가 아니라 실행이 된다.
  거짓 양성은 곧 화면의 500이라(편집 형상마다 재조립된다) 실물 아홉 그래프가 전부 통과하는
  것이 이 규칙표의 합격 조건이다
- **[TBD]** representation 축(float32·고정소수점)은 §10 백로그

## 9. 검증 — IR 실행 ↔ 생성 C 비트 일치

**[확정]** 손으로 쓴 오라클은 03-v0.13 정본 이관과 함께 사라졌으므로(그 이관의 근거는 당시 회귀
전부가 통과했다는 사실이고 git 이력에 남아 있다), 지금 남은 이중 구현은 같은 IR의 두
백엔드뿐이다. 전부 배정밀도·동일 연산 순서라 **목표는 근사가 아니라 비트 일치**이며 대조에
허용오차를 두지 않는다 — 두면 진짜 어긋남이 그 아래 숨는다.

- 최상위는 **실제 데모 미션 18,000 제어 틱**을 재생해 대조하며(모드 4개 전환·게인 스케줄
  이동·리미터 작동·타면 포화·항법 무효 홀드 포함), 그 경로들을 실제로 밟았는지도 함께 단정한다
- 커밋된 산출물과 즉석 생성본의 동일성도 검사한다(`flight/tests`)
- **한 실행 파일 × 세 기체 이미지** (v1.12) — 대조 하네스를 한 번 컴파일하고 구 합성 기체·
  200 kg급 예제·EO/IR형 이미지를 차례로 적재해 각 기체의 분석 그래프 기록(미션 + 통합 벡터)과
  비트 대조한다. 손상 이미지는 상태 코드마다 거부되는지 본다(§6.1)
- **검증 탭은 파라미터 세트로 잰다** — 요청 기체 이미지(미션 + 벡터 + 유닛)에 값으로 꺼진
  경로를 켠 커버리지 이미지(벡터 + 유닛)를 더해 이미지마다 비트 대조하고, 라인·분기·MC/DC를
  합산한다. 판정선은 그대로다. 로더 거부 경로는 손상 이미지 유닛이 태운다. 가드의 분석
  정당화는 값(kp·ki 부호)에 기대므로 세트의 모든 이미지에서 성립할 때만 인정한다
- 이 비트 일치가 **어디서 끝나는지**는 02 §1의 **[확정] 한계**가 정본이다 — 소스가 같아도
  타깃 컴파일러·최적화 옵션·부동소수 폭 차이는 남고, 타깃에서의 확인은 FCC팀 몫이다. 생성
  헤더가 그 빌드 요구를 박는다

  읽지 않는다는 하드 규칙을 지키면서 검출력을 올리려면 **단위 대수**가 필요하고, 그것은

  스로틀과 더하는 것이 옳다. 같은 구조가 곳곳에 있다(`k_rate`: s · `k_hdot`: rad·s/m ·
  `k_pitch_turn`: rad). 변환이 파라미터 단위에 사는 한 `Gain` 출력은 미지정이 정직하다
- **각도의 세분화** (§8) — `ANGLE`을 자세각/공력각/타면각으로 쪼개면 검출력이 크게 오르지만
