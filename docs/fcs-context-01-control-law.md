# 컨텍스트 문서 1/2 — 제어법칙 (도메인·설계)

> 비행제어/유도법칙 설계툴 프로젝트의 **도메인 지식·설계 결정** 컨텍스트.

> 상태 표기: **[확정]** 결정 완료 / **[기본값]** 잠정 채택, 변경 가능 / **[TBD]** 미결

## 1. 설계 흐름 개요

공력 데이터 + 추진 + 대기모델로 6DOF 모델 구축 → 항법장치(각속도·가속도·위치 센서) 상태값 기반으로 조종면/러더/스로틀 명령 생성. 설계 순서:

1. **트림 및 선형해석** — 트림점별 조종입력·상태변수 타당성 확인, 안정성 분석
2. **SCAS** — 자세(피치/롤/요) 안정화
3. **오토파일럿** — 속도/고도/헤딩 제어
4. **유도** — 미션플래너가 생성한 임무프로파일의 경로 추종, 모드별 유도
5. **비선형 시뮬레이션 검증**

## 2. 기체 / 플랜트

### 2.1 형상
**[확정]** 델타윙, 쌍발 엔진. 조종면: 엘레베이터(엘레본) × 4, 러더 × 1. 요축 보조: 차동 추력.

### 2.2 제어면 혼합 (Control Allocation)
- 4개 엘레본: 피치 = 동시(collective), 롤 = 차동(differential)
- 면이 4개 → 여유자유도 존재. **[기본값]** 내측/외측 쌍 고정 믹싱 행렬, 최적화 기반 할당은 추후 확장
- **[TBD]** 4면 배치(내측/외측 쌍 여부), 믹싱 비율, 타면각·rate 한계

### 2.3 공력 데이터베이스
- **[확정]** CFD 기반. 축: Mach, α, β, 타면각, 고도. 정미계수 + 동미계수 포함, 사실상 전체 정보 보유
- **[확정]** α 범위: 트림 조건(속도·중량)에 따라 다르며 25°를 넘는 케이스도 존재
- **[확정]** 스톨 취급 방침: DB는 기본 충실도로 사용 (고α 박리영역의 CFD 예측 불확실성 인정). 실속은 DB 비선형성에 암묵적으로 맡기지 않고 **명시적 실속 경계 테이블**(α_stall = f(Mach, 형상조건 등))을 별도 데이터로 정의
- **[확정]** 실속 경계 정본은 **공력팀 제공** — 공력팀이 CL–α 곡선 분석으로 실속각을 식별·보정하는 것이 정상 업무 분장. 툴의 DB 추출 기능은 교차확인용 (구현 문서 §데이터 참조)
- 이 단일 경계 정의를 실속 마진 감시, 엔벨로프 표시, α 리미터(§3.6)가 공유한다
- **[TBD]** 보간 방식, 외삽 정책, 테이블 차원·크기

### 2.4 추진 / 작동기
- 쌍발, 스로틀-추력 맵 형태 상정
- **[TBD]** 작동기 특성(대역폭, rate/position limit) — 미보유 시 **[기본값]** 2차계 가정값으로 시작, 파라미터화

### 2.5 환경 / 센서·항법
- **[확정]** 지구모델 WGS-84, 표준대기(ISA). 바람/난류(Dryden), 파고·전파고도계 노이즈는 추후 확장
- **[확정]** 씨스키밍 고도 기준: 해수면 0 ft (MSL)
- **[확정]** 항법: 툴은 EKF를 구현하지 않고, 실제 항법 출력의 통계적 특성을 재현하는 **등가 오차 모델**(잡음+바이어스+지연)을 사용한다. 제어법칙은 이 항법 출력을 피드백으로 사용하며, 항법 오차에 대한 강건성을 이 모델로 평가한다. 상세는 구현 문서 §3.1
- **[기본값]** 초기 오차 수치는 GPS/INS 통합항법의 일반적 수준. 항법팀 자료 확보 시 대체
- **[설계 유의]** 항법 갱신주기가 제어주기보다 낮을 수 있음 → 제어법칙은 멀티레이트 입력을 전제로 설계

## 3. 제어법칙 아키텍처

계층 구조 (**[확정]** 고정 아키텍처 — 자유 배선 없음):

```
미션플래너 (웨이포인트 → 임무프로파일)
  └─ 유도 (모드별: 런치/디센트/고도유지/씨스키밍 + 경로추종)
       └─ 오토파일럿 (속도/고도/헤딩 명령 → 자세 명령, 주로 PI)
            └─ SCAS (자세 안정화: 피치/롤/요, PI)
                 └─ 제어면 혼합 + 차동추력 보상
                      └─ 엘레본×4, 러더, 스로틀×2
```

### 3.1 SCAS
- 피치/롤/요 자세 안정화, PI 제어 기반
- 선회 시 러더 PI 제어 + 지속 선회 유지를 위한 **워시아웃 필터**
- **[TBD]** 워시아웃 시정수 결정법, 피드백 구조 상세(각속도만 vs 자세 포함), 안티와인드업 방식

### 3.2 오토파일럿
- 속도 / 고도 / 헤딩(기수) 제어, 주로 PI
- 요축: 러더 명령 + 차동추력 스로틀 출력 보상
- **[기본값]** 속도/고도/헤딩 명령 경로에 1차 명령필터 — 급격한 명령으로 인한 타면 포화·과도 하중 방지. 시정수는 **[TBD]**

### 3.3 유도
- **[확정]** 웨이포인트 열로부터 경로 생성 → 경로 추종
- 출력: 속도/고도/헤딩 명령
- **[TBD]** 경로추종 알고리즘(LOS/L1/벡터필드), 웨이포인트 전환 조건, 모드 전환 로직

#### 3.3.1 비행 모드 목록

**[확정]** 체계 유형: **선상 발사형(편도) 비행체**. 모드는 발사→종말의 비행단계(phase) 순으로 구성되며, 각 모드가 오토파일럿에 넘길 명령(속도/고도/헤딩 활성화·유지 방식)을 정의한다.

| 단계 | 모드 | 설명 |
|---|---|---|
| 발사 | 부스트 (Boost) | 부스터 추력으로 초기 가속·상승 (발사 직후) |
| 천이 | 천이 (Transition) | 부스터 분리, 지속추진 점화, 날개/핀 전개, 순항자세로 전환 |
| 중기 | 상승 (Climb) | 순항 고도까지 상승 (상승률/피치 제한) |
| 중기 | 순항 (Cruise) | 속도+고도+헤딩 동시 유지 |
| 중기 | 고도유지 (Altitude Hold) | 지정 고도 유지 |
| 중기 | 디센트 (Descent) | 씨스키밍 고도로 하강 |
| 중기 | 씨스키밍 (Sea-Skimming) | 해면 초저고도 유지 (기준 MSL 0 ft, §2.5) |
| 중기 | 웨이포인트 항법 (Waypoint Nav) | 경로 자동 추종 (경로추종 알고리즘 적용) |
| 종말 | 팝업 (Pop-up) | 종말 상승 기동 |
| 종말 | 종말 다이브 (Terminal Dive) | 최종 하강 |

- **[기본값]** 위 목록으로 시작. 임무 요구에 따라 가감. (RTL·로이터 등 회수형 모드는 편도 체계에 미적용)
- **[설계 유의]** 델타윙은 유도항력이 커 선회 시 속도·고도 손실이 두드러짐 → 선회 시 **엘리베이터/스로틀 피드포워드 보상**으로 고도 강하 방지 (일반 고정익보다 중요). SCAS/오토파일럿 협조 항목
- **[설계 유의]** 천이 단계는 형상·질량·추진 특성이 급변(부스터 분리, 날개 전개)하므로 트림점·게인 스케줄이 별도 취급되어야 함
- **[TBD]** 각 모드의 진입·이탈(전환) 조건, 모드 간 우선순위, 비상 처리
- **[확정]** 모드 전환 로직은 **선언적 모드 테이블 + 실행기(sequencer)** 로 구현. Stateflow식 시각적 상태머신 도구는 불필요·미사용
  - 근거: 비행단계가 대부분 순차 진행이고 분기가 단순 → 각 모드가 {진입조건, 활성 명령, 이탈조건}을 갖는 테이블로 충분. 다이어그램 대비 가독성·버전관리(diff)·웹 UI 편집 모두 유리
  - 단, 전환 순간의 **범프리스 처리**(적분기 초기화, 명령 페이딩)는 별도 제어법칙 설계 항목으로 남음 (§3.4 참조)
- **[범위 註]** 종말 유도의 상세 알고리즘(표적 교전 로직 등)은 본 컨텍스트의 아키텍처·분류 범위를 벗어나며, 별도 설계 단계에서 다룬다

### 3.4 게인 스케줄링
- **[확정]** 스케줄 변수: **Mach, 고도, 연료량** — 조건 조합의 트림점에서 설계
- **[확정]** 스케줄 검증 요구: 설계점뿐 아니라 **설계점 사이 보간 구간**의 안정성 확인 — 중간점에서 보간 게인 + 해당 조건 선형모델로 마진 재계산(마진 맵 기능 재사용, §4.2). 게인 테이블 불연속 검출 포함
- **[기본값]** 스케줄 변수 처리: 유효범위 밖 외삽 금지(경계값 고정), 스케줄 변수 입력 필터링으로 게인 채터링 방지
- **[TBD]** 설계점 격자, 설계점 간 보간, 보간 구간 검증점 밀도, 모드/게인 전환 시 범프리스 처리

### 3.5 이산화 / 샘플레이트
- **[확정]** 제어주기 100 Hz 시작, 추후 50 Hz 하향 및 **영향성 비교** 예정
- **[확정 설계원칙]** 이산화 계수는 주기로부터 자동 계산(Tustin 등) — 주기는 설계의 자유변수

### 3.6 엔벨로프 보호 — 받음각 리미터
- **[확정]** 제어법칙에 α 리미터 포함, 실속 진입 자체를 방지
- 제한값: α_max = α_stall(실속 경계 테이블, §2.3) − 보호마진
- 위치: 피치축 명령 경로에서 자세/α 명령 제한 상정
- **[TBD]** 보호마진 값(예: 2~3°), 하드/소프트 리미터, 오토파일럿 명령 제한 vs SCAS 내 제한, 리미터 작동 시 적분기 처리
- **[TBD]** 하중배수(Nz) 제한 필요 여부 — 팝업/종말 다이브 등 기동 시 구조하중 보호 관점. 구조 하중 한계 데이터 확보 시 결정 (α 리미터와 동일하게 피치 명령 경로 제한으로 구현 가능)

## 4. 트림 및 선형해석

### 4.1 트림
- 목적: 트림 비행상태 유지를 위한 조종입력·상태변수 타당성 확인 (MATLAB `trim` 대체)
- 방법: 비행조건별 구속조건 하 비용함수 최소화
- **[확정]** 초기에는 수평정상비행 트림부터, 정상선회·상승 트림은 추후 추가
- 케이스: 트림 컨디션 × 속도 × 고도 × 연료량 → **100+ 케이스 배치 해석**
- **[기본값]** 배치 자동 판정: 각 트림해에 판정 플래그 부여 — ① 힘·모멘트 잔차 허용범위 이내 ② 조종면·스로틀 포화 여부(리미트 대비 여유) ③ 실속 경계 대비 α 여유 ④ 인접 케이스 간 트림해 연속성(급변 시 이상 플래그). 100+ 케이스는 육안 확인 불가 → 판정 결과가 트림 가능 영역 표시·마진 맵의 근거. `TrimResult` 계약에 판정 플래그 포함 (모듈 문서 §4)
- **[TBD]** 판정 허용치 수치(잔차·포화 여유·연속성 기준) — 트림(M9) 구현 시
- 알려진 리스크: 초기값 민감성 → **[TBD]** 대응 전략(다중 초기값, 인접 케이스 시드 등)은 데이터 확인 후

### 4.2 선형화 / 안정성 해석
- **[확정]** 트림점별 구간 선형화 (수치섭동 상정)
- 횡축(lateral-directional) / 종축(longitudinal) 분리 해석
- **[기본값]** 작동기·지연 포함: 마진 계산용 선형모델에는 작동기 동특성(§2.4 가정값)과 주요 지연(항법 출력·제어주기)을 포함하는 것을 기본으로 한다 — 작동기·지연 제외 마진은 낙관적. 포함/미포함 선택 옵션으로 영향 분리 분석 지원
- **[TBD]** 지연의 선형 표현 방식(Padé 차수 등)·포함 범위 상세 — 선형화(M9) 구현 시
- **[기본값]** 평가지표: 고유치·감쇠비(단주기, 장주기, 더치롤, 롤, 스파이럴), 이득·위상여유. 필요 시 MIL-F-8785C류 비행성 기준 추가
- **[확정]** **마진 맵**: 이득·위상여유를 Mach-고도-연료 격자 전체에 대해 계산, 비행영역 내 마진 취약 구간 식별. 100 vs 50 Hz 마진 변화 비교도 동일 기능으로 수행

## 5. 검증 기준 (제어법칙 관점)

- **[기본값]** 합격기준은 일반 기준: 오버슈트, 정착시간, 정상상태 오차, 경로오차 한계. 허용오차 수치는 폐쇄망 Simulink 대조 시 확정
- **[확정]** 합격기준 수치는 파라미터 관리 계층(구현 문서 §5.5)으로 관리 — 판정 기준이 파라미터 지문에 포함되어 산출물 계보·Δ리포트에 요구도 버전이 자동 반영됨
- **[확정]** 엔벨로프 감시 요구: 실속 마진(α_stall − α) 시계열, 임무프로파일 전체 최악 마진 요약, DB 유효범위 이탈 플래그(실속 판정과 별개)
- 스톨 충실도 한계: 실속 진입 거동은 DB 범위 내 재현 가능하나 실속 후 동적 효과(히스테리시스 등)는 정적 테이블로 재현 불가. 목적은 실속 후 거동 예측이 아니라 **실속 회피 설계·검증**
- **[확정]** 최종 검증은 기존 Simulink 모델과 대조 (보안상 설계 중 참조 불가, 완성 후 검증만 가능)
